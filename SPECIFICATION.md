# Техническое задание (ТЗ): Автономное приложение для мониторинга воздушных тревог и воздушной обстановки (Kotlin Multiplatform)

## 1. Общее описание и архитектура проекта
**Цель:** Разработать полностью автономное (serverless) приложение для отслеживания воздушных тревог и приблизительного положения воздушных целей (БПЛА, ракеты, баллистика) в Украине в реальном времени. Приложение привязывает оповещения к текущей геолокации или выбранным точкам на карте, имеет гибкий «Ночной режим» и настраиваемую деликатную вибрацию.

**Архитектура:** Kotlin Multiplatform (KMP) с Compose Multiplatform для общего UI.  
**Целевые платформы на текущем этапе:** Модуль `:composeApp` с таргетом **Android** (`minSdk = 26` / Android 8.0, `targetSdk = 35` / Android 15), но с полным разделением логики на `commonMain` и `androidMain` для лёгкого добавления iOS или Desktop в будущем.

### Стек технологий (строго совместимый с KMP)
* **UI и Навигация:** Compose Multiplatform (Material 3), Jetpack Navigation Compose для KMP (или Voyager).
* **Сеть и сериализация:** Ktor Client (`ktor-client-core` в `commonMain`, `ktor-client-okhttp` в `androidMain`) + `kotlinx.serialization`.
* **Локальное хранилище:** Jetpack DataStore (`androidx.datastore:datastore-preferences-core` для KMP) для настроек и статусов + Room KMP (или SQLDelight) для кэширования справочника регионов и сохранённых точек.
* **Дата и время:** `kotlinx-datetime` (для расчёта расписания ночного режима и длительности тревог).
* **DI (Внедрение зависимостей):** Koin (`koin-core`, `koin-compose`).
* **Нативные Android-модули (`androidMain`):** `ForegroundService`, `NotificationManager` + `VibrationEffect`, `osmdroid` (OpenStreetMap), Google Play Services Location API, системный `Geocoder`.

## 2. Разделение модулей (`commonMain` vs `androidMain`)
Проект должен быть спроектирован так, чтобы максимум бизнес-логики и интерфейса находилось в общем коде:

### `commonMain` (Общий код)
* Модели данных, сетевые клиенты для API `ukrainealarm.com` и `neptun.in.ua`.
* Репозитории, логика кэширования справочника регионов и сохранённых пользователем точек.
* Бизнес-логика проверки «Тихих часов» (Ночного режима) на базе `kotlinx-datetime`.
* Алгоритм расчёта дистанции от активной точки до воздушной цели (формула Гаверсинуса).
* Логика защиты от дублей уведомлений (дедупликация событий).
* Весь пользовательский интерфейс (Onboarding, главный экран с вкладками, экран точек, настройки, модальные окна), кроме самой подложки карты (подключается через `expect/actual`).

### `androidMain` (Платформенная реализация)
* Реализация карты через `AndroidView` с библиотекой `osmdroid` (с кэшированием тайлов на диск).
* Фоновая служба `ForegroundService` и `BroadcastReceiver` для автозапуска после перезагрузки (`BOOT_COMPLETED`).
* Системные уведомления (`NotificationChannel`) и управление паттернами вибрации (`VibrationEffect`).
* Получение GPS-координат (`FusedLocationProviderClient`) и обратное геокодирование (`Geocoder`).

## 3. Источники данных (Гибридная автономная схема)
Приложение работает без промежуточного бэкенда, напрямую со смартфона, объединяя два источника данных:

1. **Основной источник тревог (Официальный):** API «Повітряна тривога» (`api.ukrainealarm.com`).
   * Используется для определения статуса тревоги по регионам/громадам и генерации уведомлений.
   * **Оптимизация трафика и батареи:** Фоновый сервис опрашивает лёгкий эндпоинт `GET /api/v3/alerts/status` (возвращает ID последнего события в стране). Полный список активных тревог запрашивается только при изменении этого ID.
2. **Дополнительный источник воздушных целей (OSINT-радар):** API проекта NEPTUN (`neptun.in.ua/api/v1/threats` или WebSocket `/api/v1/stream`).
   * Используется исключительно для визуализации приблизительного положения БПЛА, крылатых/баллистических ракет и авиации на карте.
   * **Отказоустойчивость:** Сбой, таймаут или недоступность сервера NEPTUN не должны влиять на работу основного мониторинга тревог от `ukrainealarm.com`.
   * **Обязательная атрибуция:** В интерфейсе карты или разделе «О приложении» разместить кликабельную ссылку на источник (NEPTUN) и пометку: *«Положение целей является ориентировочным»*.

## 4. Сценарий первого запуска (Onboarding Flow)
При первом открытии приложение проверяет флаг `isOnboardingCompleted` в `DataStore`. Если он `false`, запускается линейный пошаговый мастер из 4 экранов:

1. **Шаг 1: Приветствие и дисклеймер**
   * Краткое объяснение принципа автономной работы и предупреждение об ориентировочном характере данных на карте.
   * Кнопка «Начать настройку» (в фоне в этот момент запускается первичная загрузка и кэширование справочника регионов из `ukrainealarm.com`).
2. **Шаг 2: Критические разрешения (Уведомления и Батарея)**
   * Две карточки с визуальным индикатором статуса (не выдано / выдано):
     * *Разрешение на уведомления:* вызывает системный запрос `POST_NOTIFICATIONS`.
     * *Работа в фоне без ограничений:* вызывает системный диалог `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` с краткой поясняющей подсказкой.
   * Кнопка «Далее» (и опциональная кнопка «Настроить позже»).
3. **Шаг 3: Выбор первой локации для отслеживания**
   * Предложение выбрать стартовый режим мониторинга:
     * *Вариант А («Моя геолокация»):* запрашивает права `ACCESS_FINE_LOCATION` (с пояснением необходимости `ACCESS_BACKGROUND_LOCATION` для работы при перемещении).
     * *Вариант Б («Выбрать точку на карте»):* открывает карту с прицелом по центру для установки первого маркера (например, «Дом») без необходимости давать доступ к GPS.
4. **Шаг 4: Быстрая настройка комфорта (Ночь и Вибрация)**
   * Переключатель «Включить ночной режим (23:00 – 07:00)».
   * Выбор пресета деликатной вибрации с кнопкой «Проверить» прямо на этом экране.
   * Кнопка «Завершить» — сохраняет `isOnboardingCompleted = true`, запускает `ForegroundService` и переводит пользователя на главный экран.

## 5. Структура навигации и экраны приложения
После завершения Onboarding открывается основной интерфейс с нижней панелью навигации (**Bottom Navigation Bar**) из **3 вкладок**:

### Вкладка 1: «Карта» (Главный экран по умолчанию)
* **Верхняя Sticky-карточка статуса:**
  * Отображает статус активной (или ближайшей) точки: спокойный зелёный фон при отсутствии тревоги (*«г. Каменское (Дом) — Тревоги нет»*) или контрастный красный с живым таймером длительности при тревоге (*«Воздушная тревога • 00:14:22»*).
  * Горизонтальный свайп по карточке переключает фокус между сохранёнными точками пользователя с плавным центрированием карты на выбранном маркере.
* **Центральная область (Интерактивная карта `osmdroid`):**
  * Реализуется через `expect @Composable fun AlertMapView(...)`.
  * Отображает маркеры всех сохранённых точек пользователя: зелёный/синий маркер — тревоги нет; красный пульсирующий маркер — активна тревога.
  * Отображает слой воздушных целей (векторные иконки БПЛА, ракет, баллистики), повёрнутых на угол `bearing` (азимут движения из JSON).
  * **Экономия заряда:** Слой воздушных целей (`NEPTUN API`) опрашивается **только пока открыта вкладка «Карта»** (привязка к `Lifecycle`).
* **Плавающие кнопки (FAB) поверх карты:**
  * Тумблер быстрого включения/отключения слоя воздушных целей (БПЛА/ракеты).
  * Кнопка «Центрировать на моей геопозиции».
  * Кнопка «+ Добавить точку» (установка пина по центру экрана или поиск адреса).
* **Нижняя строка:** Полупрозрачная подпись с дисклеймером и ссылкой на NEPTUN.

### Вкладка 2: «Мои точки» (Управление локациями)
* **Блок «Моя геолокация»:** Переключатель вкл/выкл автоматического отслеживания текущего местоположения по GPS с отображением определённого региона/громады.
* **Список сохранённых точек:** Карточки всех маркеров («Дом», «Работа», «Родители» и др.). Каждая карточка содержит:
  * Название точки, привязанный регион/громаду и текущий статус (тихо / тревога).
  * Индивидуальный переключатель «Уведомлять по этой точке».
  * Действия: переименовать, изменить позицию на карте, удалить.
* **Кнопка «Добавить локацию»:** Открывает `BottomSheet` с поиском населённого пункта (через `Geocoder` / Nominatim) или выбором точки на карте. По координатам точки приложение автоматически находит соответствующий `regionId` в справочнике `ukrainealarm.com`.

### Вкладка 3: «Настройки»
* **Блок 1: Уведомления и деликатная вибрация**
  * Выбор пресета вибрации (`VibrationEffect`):
    1. *Без вибрации.*
    2. *Ультра-мягкий импульс* (однократный короткий тактильный отклик 80–100 мс с низкой амплитудой).
    3. *Деликатный двойной стук* (0 мс пауза, 80 мс вибро, 120 мс пауза, 80 мс вибро).
    4. *Стандартная вибрация.*
  * *Техническое требование:* Так как Android запрещает менять вибрацию у существующего `NotificationChannel`, при смене пресета старый канал удаляется (`deleteNotificationChannel`), и создаётся новый с обновлённым ID (`alert_channel_vX`).
  * Выбор звука уведомления.
  * Кнопка **«Тест уведомления»** для мгновенной проверки выбранной вибрации и звука.
* **Блок 2: Ночной режим («Тихие часы»)**
  * Переключатель вкл/выкл, выбор временного интервала (по умолчанию `23:00 – 07:00`) и дней недели.
  * Выбор сценария поведения ночью:
    * *Полная тишина:* уведомление приходит в шторку без звука, без вибрации и без включения экрана.
    * *Только ультра-мягкий импульс* (без звука).
    * *Фильтр отбоев:* не беспокоить при отбое тревоги ночью, но уведомлять о начале тревоги.
* **Блок 3: Радар и дистанция**
  * Настройка радиуса предупреждения (например, 30 км): подсветка или уведомление, если воздушная цель приблизилась к активной точке ближе заданного расстояния.
* **Блок 4: Диагностика фоновой работы**
  * Наглядный чек-лист состояния системы: статус `ForegroundService`, статус отключения оптимизации батареи, наличие разрешения на уведомления и геолокацию с кнопками быстрого исправления, если разрешение было отозвано.

### Вспомогательные модальные окна (`BottomSheet`)
* **Детали точки (по тапу на маркер на карте):** Показывает точный регион/громаду, время последней проверки и длительность активной тревоги.
* **Детали цели (по тапу на иконку БПЛА/ракеты):** Показывает тип цели, курс движения и приблизительное расстояние до ближайшей точки пользователя.

## 6. Требования к надёжности, безопасности и фоновой работе
1. **Защита от дублей (Дедупликация):** Приложение хранит в `DataStore` последний обработанный статус и ID события для каждой точки. Повторное уведомление отправляется строго при реальном переходе состояния (`НЕТ ТРЕВОГИ -> ТРЕВОГА` или `ТРЕВОГА -> ОТБОЙ`), исключая спам при переподключении к интернету.
2. **Foreground Service (`androidMain`):** Постоянная служба опроса `ukrainealarm.com` с тихим компактным уведомлением в шторке (`IMPORTANCE_LOW`), отображающим актуальный статус (*«Мониторинг активен • Дом: Тревоги нет»*).
3. **Автозапуск:** `BroadcastReceiver` на `BOOT_COMPLETED` для старта фонового мониторинга сразу после перезагрузки устройства.
4. **Устойчивость к обрывам сети:** Обработка потери интернета без падения службы (экспоненциальная задержка повторных запросов и мгновенное возобновление при появлении связи через `ConnectivityManager.NetworkCallback`).
5. **Безопасность API-ключа:** Ключ от `ukrainealarm.com` хранится в `local.properties` и пробрасывается в код через `BuildKonfig` (или `BuildConfig`), не попадая в систему контроля версий Git.

## 7. Пошаговый план разработки для агента
1. **Инициализация KMP-проекта:** Создать структуру Kotlin Multiplatform + Compose Multiplatform (таргет Android, `minSdk = 26`, `targetSdk = 35`). Настроить `libs.versions.toml` с библиотеками Ktor, Koin, `kotlinx-serialization`, `kotlinx-datetime`, DataStore KMP, Room KMP и `osmdroid`.
2. **Общий слой данных (`commonMain`):** Реализовать клиенты API для `ukrainealarm.com` и `neptun.in.ua`, модели данных, кэширование справочника регионов, расчёт дистанций (Гаверсинус), дедупликацию и логику «Тихих часов».
3. **Платформенные сервисы (`androidMain`):** Реализовать `ForegroundService` для фонового опроса, `BroadcastReceiver` на перезагрузку, менеджер каналов уведомлений с динамическим пересозданием канала под `VibrationEffect` и получение GPS-координат.
4. **Карта и визуализация:** Реализовать `expect/actual` компонент `AlertMapView` на базе `osmdroid` с кэшированием тайлов, установкой маркеров пользователя, привязкой координат к `regionId` и слоем иконок дронов/ракет с поворотом по курсу `bearing`.
5. **UI и Навигация (`commonMain`):** Сверстать пошаговый Onboarding (4 экрана), нижнюю навигацию (Карта, Мои точки, Настройки) и модальные карточки деталей.
